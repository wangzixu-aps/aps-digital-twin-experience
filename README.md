# 轻量 APS + 数字孪生 + MRP —— 项目经验与技术复盘

> 一个面向中小离散制造的计划/仿真型数字孪生系统。核心目的是把「MRP 净需求展开 → 有限产能排产 → 数字孪生推演 → 扰动重排」串成一条闭环。这是我大二做的大创项目，这个仓库用来沉淀过程中踩过的坑和想通的设计。
>
> **本仓库是项目经验与技术复盘，不是源码。** 项目源码因商业计划暂不公开，这里的是开发过程中的设计决策、踩坑与可复用的经验。

---

## 一句话定位

给中小离散制造企业一个「**算得对、改得动、看得见**」的排产工具：先用 MRP 算物料齐套、再用有限产能求解器排设备时间、把结果推演成车间数字孪生、注入扰动自动重排、最后用「计划 vs 实际」对比告诉计划员哪里会出问题。

三个关键词，缺一不可：

- **MRP** —— 负责「料够不够」，两遍展开算物料缺口与按单齐套；
- **APS** —— 负责「设备排得下排不下」，限时求高质量可行解；
- **数字孪生** —— 负责「排出来长什么样」，把计划态推演成车间画面，并支持扰动重排。

三者不是三个并列功能，而是一条流水线：**MRP 算料 → APS 排设备 → 孪生推演 + 扰动重排**。

---

## 为什么这个组合值得做

中小离散制造企业的真实困境是「有 ERP 但排产靠老师傅脑子」。老师傅一走，排产能力就没了。而市面上的重 APS 要么太贵、要么要求接入 IoT 改造产线，要么计划员因为结果不直观不信任系统——恰恰是中小厂最大的问题。

这个项目刻意的取舍是：**不接 IoT、不改造硬件**。数字孪生的「实时状态」不是来自传感器，而是来自排产计划的推演（计划说这台设备该在加工，孪生里它就显示在加工）。设备坏了由工人手动标记，系统进行重排。

## 系统全景

```
订单（自然语言/AI 解析/Excel 导入，人工确认）
        │
        ▼
总展开 ──► 每个物料总缺口 ──► 建议采购（保证总量一定够）
        │
        ▼
按单展开 ──► 从到货出发、连同下层展开 ──► 每单齐套 + 自产量 + 工时
        │
        ▼
有限产能排产（求解器，限时高质量可行解）
        │
        ▼
数字孪生3D展示
        │
        ▼
扰动注入（设备故障/插单/延期/物料短缺…）
        │
        ▼
重排（冻结窗口 + 计划 vs 实际对比）
```

## 我踩过的最有价值的坑（一句话版）

> 完整版见 `docs/articles/`，这里只给结论。

1. **毛需求 = 上级「净需求」× 用量，不是「毛需求」下推** —— 多级 BOM 最容易算错的一条，错了不报错，只在最后数字对不上。
2. **低层码不能落库，只能现算** —— 存了就得保证每次改 BOM 都重算，漏一次就把共用件算早一层、净需求偏小且静默出错。
3. **「总量够」≠「时序够」** —— 物料约束必须带时间轴，否则会放行「第 5 天开工、第 20 天才到货」的缺料方案。
4. **加权目标函数会「理性地」牺牲紧急订单** —— 优先级要做成硬约束 + 自动降级，而不是权重。
5. **如期到货不是扰动，是输入前提** —— 把「到货」当成重排触发条件，会重蹈计划震荡。

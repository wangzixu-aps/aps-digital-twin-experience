# 「总量够」≠「时序够」：库存约束为什么必须带时间轴

> 关键词：排产、库存约束、物料到货、时序
> 项目背景：排产时如何保证「不会安排缺料的生产」。本文复盘一个我从「必要条件」到「充分条件」的认知修正——以及这个修正为什么重要。

---

## 0. 问题

排产时，某道工序需要某种物料。怎么在排产模型里保证「物料是够的」？

## 1. 第一版：总量约束

最直觉的写法是：

```
累计消耗 ≤ 初始库存 + 期间到货
```

「所有工序加起来消耗的物料，不超过我一开始有多少 + 期间会到多少。」

这个约束**是必要条件，但不是充分条件**。它忽略了时间顺序。

## 2. 反例：总量够，但时序不够

- 初始库存 0，第 20 天才到货 100 个；
- 两道工序各需 40 个，计划安排在第 5 天、第 6 天开工。

总量检查：80 ≤ 100，通过。

**但这是放行了一个缺料方案**——第 5 天要开工时，物料一个都没有（要到第 20 天才到）。总量约束根本发现不了这个问题。

## 3. 修正：带时间轴的约束

正确的形式必须带时序：

```
∀时刻 t，Σ_{开工/完工 ≤ t} 的消耗 ≤ 初始库存 + t 之前的所有到货
```

也就是说，**在每一个时间点，累计消耗都不能超过「到那个点为止」的累计到货**。

还有一个对称的坑：**滚动时域窗口太短，会把关键到货截在窗外，制造「假不可行」**。如果规划窗口只覆盖未来 7 天，而关键物料第 8 天才到，系统会误判「缺料」，其实是窗口截断了。

## 4. 更本质的认知：库存是随时间变化的「分段函数」

库存不是一个数字，是一条**随时间变化的曲线**。它只在「到货」「领料」「完工」这些事件发生时跳变，其余时间不变。

所以「某时刻库存是多少」的正确答法是**精确重放**，而不是按小时采样：

```
I(t) = 初始库存 + Σ到货(t) − Σ领料(t)
```

用二分 + 前缀和，O(log n) 就能得到任意时刻的精确库存，比采样更准、更省。

## 5. 提炼的原则

1. **物料约束必须带时间轴**，「总量够」只是必要条件；
2. **库存是分段函数**，用事件重放而非时间采样；
3. **规划窗口要覆盖全部关键到货**，否则会制造假不可行。

## 6. 总结

这个坑的本质，是「把库存当成一个数」而不是「一条随时间变化的曲线」。一旦认识到库存是时间的函数，总量约束、时序约束、规划窗口这些坑就都串起来了。

**排产里的物料约束，难点从来不是「够不够」，而是「什么时候够」。**
